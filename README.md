# MacroRelay Studio

## 2.58.4 · 시각적 분기 관리

- 분기 시작 노드에서 성공선으로 연결된 전용 흐름을 각 분기 영역에 자동으로 포함합니다.
- 다른 분기 시작점·공용 합류 노드·반복 경로는 경계로 처리해 분기가 섞이지 않습니다.
- 상단의 `선택 분기 연결`, `분기 추가·해제` 버튼에서 생성·편입·제외·이름 변경·연결 해제를 처리합니다.
- 기존 분기에 추가할 때 선택 가능한 노드만 강조되며, 해당 노드를 클릭해 소속을 지정합니다.
- 분기 제목을 더블클릭해 이름을 바꿀 수 있습니다.

## 2.58.3 · 스마트 작업 그룹에서 노드 분리

- 스마트 작업 영역 밖으로 노드를 드래그하면 그룹 소속만 해제되고 기존 연결선은 유지됩니다.
- 노드 우클릭 메뉴에서도 `스마트 작업에서 제외`을 선택할 수 있습니다.

## 2.58.2 · Studio·Player 종료 시 매크로 완전 정리

- Studio 창을 닫거나 앱이 종료되면 해당 Studio에서 실행한 AutoHotkey 매크로 프로세스 트리를 먼저 종료합니다.
- Player는 내부 상태 표시와 관계없이 소유한 매크로를 종료하며, 무한 반복 예약도 종료 중에는 다시 시작되지 않습니다.
- 각 매크로 실행 PID를 등록해 다른 Studio·Player 인스턴스가 실행 중인 매크로는 건드리지 않습니다.
- 모든 MacroRelay 매크로가 끝난 경우에만 공유 OpenCV 엔진을 종료합니다.
- 정상 완료·비상 정지·창 닫기 모두 실행 PID 표식을 정리합니다.

## 2.58.1 · 캔버스 이동 및 스마트 노드 생성 복구

- 빈 캔버스 더블클릭 드래그로 캔버스를 이동하는 기존 조작을 복원했습니다.
- `Ctrl + 빈 캔버스 더블클릭` 시 클릭 위치를 기억한 액션 선택창을 열고 선택한 노드를 그 위치에 생성합니다.
- 이미지 서치는 이미지 지정 후 검색 영역을 별도로 지정하고, 선택한 프로그램을 자동 대상 창으로 저장합니다.
- 픽셀 색상 서치는 색상 선택 후 검색 영역을 별도로 지정하며 대상 프로그램·상대 좌표·비활성 클릭을 자동 구성합니다.
- 설정 과정에서 취소하면 노드와 불필요한 이미지 자산을 생성하지 않습니다.

## 2.58.0 · 그룹 흐름 및 노드 캔버스 편의성 개선

- 접힌 노드 그룹도 외부 성공·실패 연결선을 축약 표시하고, 접기 버튼을 그룹 좌측 상단으로 옮겼습니다.
- 노드 번호를 내부 저장 순서 대신 실제 실행 흐름에 따라 표시하며 순환 연결은 `실행 N으로 복귀`로 구분합니다.
- 그룹별 다음 그룹과 미연결 성공·실패 정책을 설정해 A → B → C 작업 그룹 흐름을 구성할 수 있습니다.
- 새 노드는 기존 연결을 자동으로 변경하지 않고 지정한 캔버스 위치에 독립 노드로 생성됩니다.
- 그룹 안 노드는 그룹 색상을 함께 표시하며, 다중 선택 후 우클릭으로 한 번에 접거나 펼칠 수 있습니다.
- 노드 접기·펼치기 시 같은 행의 노드 간격을 자동으로 압축하거나 복원합니다.

## 2.57.4 · 플레이어 미니 모드 간소화

- 미니 모드에는 실행 중이거나 선택된 매크로 이름과 `실행`, `일시정지`, `종료` 버튼만 표시합니다.
- 미니 모드에서도 일시정지 상태에 따라 버튼이 `재개`로 즉시 바뀝니다.
- `F8` 또는 미니 창 더블클릭으로 일반 모드로 돌아갈 수 있습니다.

## 2.57.3 · 독립 플레이어 실행 및 현재 노드 표시

- 바탕화면의 `MacroRelay Player` 바로가기로 Studio 없이 플레이어를 직접 실행할 수 있습니다.
- AutoHotkey 진행 파일의 UTF-8 BOM을 정상 처리해 현재 실행 중인 노드 번호·이름·액션을 실시간 표시합니다.
- 새 실행과 반복 실행 때 이전 진행 상태를 초기화하고 첫 노드 준비 상태부터 명확하게 표시합니다.
- 플레이어 단독 실행 시 프로젝트의 번들 패키지와 OpenCV 런타임을 자동 연결합니다.

## 2.57.2 · 이미지 검색 설정·실행 일치 보정

- `찾으면 클릭`을 끈 경우 과거에 저장된 멀티 클릭 대상값이 클릭을 다시 활성화하지 않도록 수정했습니다.
- 클릭을 꺼도 선택한 활성/비활성 클릭 방식은 보존되어 다음 편집 때 설정이 되돌아가지 않습니다.
- 실시간 검사기와 실제 노드가 동일한 OpenCV 프로필·배율·투명 마스크 알고리즘으로 이미지를 판정합니다.
- `이미지 사라짐 대기` 노드는 검사기에서도 실제 실행과 동일하게 이미지가 없어야 성공으로 표시됩니다.
- 기본 Python이 없는 PC에서도 대체 실행기가 번들 OpenCV·NumPy 경로를 자동 연결해 Studio가 정상 실행됩니다.

## 2.57.1 · 다중 픽셀 영역 색상 검색

- 다중 픽셀 체크를 고정 좌표 비교에서 지정 영역 내 동일 색상 탐색으로 확장했습니다.
- 저장된 대상 프로그램을 최우선으로 캡처해 앞에 떠 있는 다른 창이 대상으로 바뀌지 않게 했습니다.
- 노드 우측 상단 `▦` 버튼으로 실시간 영역 검사를 바로 열 수 있습니다.
- 클릭 방식은 비활성 클릭이 기본이며, 화면을 한 번 클릭해 오프셋을 자동 계산할 수 있습니다.
- 검색 영역이 없는 기존 노드는 기존의 1픽셀 좌표 검사 방식으로 그대로 실행됩니다.
- 멀티 이미지 시각 검사기와 신뢰도 설정창에서 제거한 이미지는 노드의 목록·영역·오프셋·분기에서도 함께 제거됩니다.
- `이미지 사라짐 대기`는 대상이 없는 성공 상태에서 클릭하거나 같은 노드를 무한 재검색하지 않도록 안전 보정됩니다.

## 2.57.0 · 다중 픽셀 동일 프레임 조건 검사

- 첫 픽셀을 선택한 프로그램을 자동 감지하고 이후 핀을 해당 프로그램의 클라이언트 상대 좌표로 저장하여 창이 이동해도 같은 위치를 검사합니다.
- 선택한 픽셀 번호·저장 색상·현재 색상·허용 오차·일치 여부를 대상 화면 위에서 확인하는 실시간 미리보기 창을 추가했습니다.
- 모든 픽셀을 한 번 캡처한 동일 프레임에서 판정하며 `모두`, `1개 이상`, `N개 이상`, `정확히 N개` 조건을 지원합니다.
- 검사 간격, 검색 제한 시간, 연속 확인 횟수, 색상 허용 오차, 일치 개수 변수 저장을 지원합니다.
- 성공 시 분기만 수행하거나 첫 일치 픽셀·지정 번호 픽셀을 일반/비활성 방식과 오프셋으로 클릭할 수 있습니다.
- 다중 픽셀 결과를 실제 노드 True/Fail 흐름에 연결하고 기존 전체 화면 절대 좌표 JSON은 자동 변환 없이 그대로 유지합니다.

## 2.56.1 · 이미지 지정·상세 편집 정밀 확대

- 최초 이미지 지정 화면에서 마우스 휠로 커서 위치를 중심으로 최대 1600%까지 확대·축소하고, 가운데 버튼 드래그로 화면을 이동할 수 있습니다.
- 이미지 상세 편집창에서도 보조키 없이 휠로 확대·축소하며 선택 영역이 확대 전과 동일한 원본 픽셀을 계속 가리킵니다.
- 확대는 보기 배율에만 적용됩니다. 저장 PNG의 해상도·픽셀·검색 영역과 OpenCV 이미지 서치 입력은 변경하지 않습니다.
- 두 화면 모두 숫자 `0` 키로 즉시 100% 배율로 돌아갑니다.

## 2.56.0 · 멀티 이미지별 분기선 시각화

- 멀티 이미지 서치에서 개별 이미지에 지정한 `True/Fail` 목적지를 얇은 청록·분홍 점선으로 캔버스에 표시합니다.
- 선 라벨에 이미지 순번·이름·판정·목적지 노드를 함께 표시하고, 같은 판정과 목적지로 향하는 여러 이미지는 한 선으로 묶습니다.
- 분기선에 마우스를 올리면 해당 이미지 미리보기가 나타나며, 더블클릭하거나 우클릭하면 해당 이미지 설정 행으로 바로 이동합니다.
- 캔버스 상단의 `개별 분기선` 버튼으로 보조선을 즉시 숨기거나 다시 표시할 수 있습니다.

## 2.55.1 · 조건 분기선 노드 관통 방지

- 조건 분기선은 성공이면 노드 위쪽, 실패면 아래쪽의 충돌 없는 외곽 차선으로 자동 우회하여 중간 노드를 관통하지 않습니다.
- 같은 구간을 지나는 여러 조건선은 서로 다른 외곽 차선을 자동 배정받으며, 사용자가 직접 편집한 수동 경로는 그대로 보존합니다.

## 2.55.0 · 멀티 이미지별 True/Fail 분기

- 멀티 이미지 서치의 각 이미지에 `True`와 `Fail` 분기 버튼을 추가하고, 버튼을 누른 뒤 실제 노드 캔버스에서 다음 노드를 클릭해 지정할 수 있습니다.
- 이미지별로 지정하지 않은 결과는 기존 노드 전체의 성공·실패 연결을 그대로 사용합니다. 예를 들어 `True`만 지정하면 `Fail`은 기존 실패선을 따릅니다.
- 노드 삭제·이동, 자동화 블록 저장·삽입 과정에서도 이미지별 분기 대상 번호를 안전하게 다시 맞춥니다.
- 미리보기 목록을 열 때 전체 PNG를 반복 디코딩하고 목록을 여러 번 다시 그리던 처리를 썸네일 캐시·일괄 갱신 방식으로 바꿔 끊김을 줄였습니다.

## 2.54.3 · 멀티 이미지별 클릭 오프셋 실행 보정

- 실시간 검증창에서 저장한 이미지별 클릭 오프셋을 노드 상세 편집기의 두 내부 컨트롤에 함께 반영하여 이전 값으로 되돌아가는 문제를 막았습니다.
- `첫 번째 발견 이미지 클릭`에서 OpenCV가 실제로 발견한 이미지 번호의 개별 오프셋을 선택해 한 번만 클릭합니다.
- 예를 들어 5번 이미지가 발견되면 1~4번의 값이나 공통 중심점이 아니라 5번 이미지에 저장한 오프셋이 적용됩니다.

## 2.54.2 · 실시간 검증창 가독성 개선

- 검색 영역 실시간 검증창을 현재 모니터의 사용 가능 영역에 맞춰 기본적으로 크게 열어, 이미지가 많아도 매번 창을 수동으로 키울 필요가 없습니다.
- 왼쪽 설정·이미지 목록 패널을 기본 500~560px로 넓혀 긴 문구와 이미지 이름이 잘리는 현상을 줄였습니다.
- 작은 모니터에서는 작업 표시줄과 화면 경계를 넘지 않도록 창 크기와 위치를 자동 제한합니다.

## 2.54.1 · 멀티 이미지 클릭 오프셋 간편 지정

- 검색 영역 실시간 검증의 각 이미지 카드에서 버튼을 누르고 오른쪽 화면의 실제 클릭 위치를 한 번 찍어 오프셋을 설정할 수 있습니다.
- 확대·축소된 화면 좌표를 원본 프레임으로 환산하고, 발견된 해당 이미지 중심과의 차이를 이미지별 오프셋으로 저장합니다.
- 우클릭으로 합친 멀티 이미지 서치의 기존 이미지별 오프셋 보존과 OpenCV 실행 경로를 검증했습니다.

## 2.54.0 · 애니메이션 서치

- 검색할 애니메이션 영역을 한 번 드래그하면 약 1.2초 동안 프레임을 자동 수집합니다.
- 시간에 따라 바뀌는 회전 효과·배경 픽셀은 자동으로 투명화하고, 안정적인 아이콘 부분이 남은 대표 PNG를 최대 4개 생성합니다.
- 대표 프레임 중 하나만 일치해도 성공하는 OpenCV 검색으로 실행되며 대상 프로그램과 클라이언트 상대 검색 영역도 자동 설정합니다.
- 일반 노드 추가와 스마트 녹화 빠른 추가 양쪽에서 사용할 수 있고, 기존 이미지 미리보기·상세 편집·비활성 클릭 설정을 그대로 지원합니다.

## 2.53.0 · 노드 그룹 접기·펼치기

- 노드 그룹 헤더의 화살표를 누르거나 헤더를 더블클릭하면 그룹 내부 노드를 한 번에 숨기거나 다시 표시합니다.
- `노드 그룹` 메뉴에서 선택 그룹 또는 모든 그룹을 한 번에 접고 펼칠 수 있습니다.
- 접힌 상태는 매크로의 `graph_comments[].collapsed`에 저장되어 다음 실행에서도 그대로 복원됩니다.
- 접힌 그룹을 이동하면 숨겨진 내부 노드 위치도 함께 이동하며, 그룹 삭제 시 내부 노드가 즉시 다시 표시됩니다.

## 2.52.0 · 개별 매크로 실행 묶음

- `실행 묶음`에서 던전·성장·상점·이벤트처럼 따로 만든 매크로를 원하는 순서로 추가하고 드래그 또는 위·아래 버튼으로 정렬합니다.
- 묶음은 기존 개별 매크로를 복사하지 않고 호출하므로, 개별 매크로를 수정하면 다음 묶음 실행부터 바로 반영됩니다.
- 입장권 없음처럼 한 매크로가 자체 종료해도 다음 매크로를 계속 실행하며 Studio의 정지 버튼으로 묶음 전체를 멈춥니다.
- 기존 실행 묶음을 선택한 상태에서 `실행 묶음`을 누르면 구성과 순서를 다시 편집할 수 있습니다.

## 2.51.1 · 멀티서치 대상 프로그램 자동 지정

- 전체 화면에서 이미지나 검색 영역을 드래그하면 해당 위치 아래의 실제 프로그램을 자동 식별해 멀티서치 대상에 저장합니다.

- 다중 모니터와 DPI 배율 환경에서 화면 절대 좌표를 대상 클라이언트 상대 좌표로 자동 변환합니다.
- Windows 원클릭 설치와 GitHub 릴리스용 Studio ZIP 생성을 추가했습니다.

- `F7 다음 작업`의 후보 실패 연결은 실행 데이터에는 유지하되 화면에서는 숨겨 작업 색상 영역만으로 간결하게 구분합니다.

- `F7 다음 작업`으로 나눈 작업들의 첫 조건을 위에서부터 검사하고, 최초로 성공한 작업 라인 하나만 끝까지 실행합니다. 모든 첫 조건이 실패하면 매크로를 종료합니다.

- 노드 플로우의 노드를 더블클릭하면 좁은 측면 선택에 그치지 않고 넓은 상세 설정 창을 바로 엽니다.

- 이미지 서치 노드를 2개 이상 선택한 뒤 우클릭해 멀티 이미지 서치 하나로 합칠 수 있으며 실시간 보드와 일반 노드 플로우에서 모두 지원합니다.

- 스마트 녹화창에 드래그 가능한 실시간 노드맵을 표시해 클릭·입력·조건·대기·이미지 캡처가 기록되는 즉시 확인할 수 있습니다.

- 녹화 중 배치한 실시간 노드 위치를 최종 매크로 노드 배치에 이어서 사용합니다.

## 2.44.0 · AI 30초 영상 판단 테스트

- `AI 영상 테스트`는 최대 30초 동안 화면을 5fps 연속 영상으로 녹화하고 클릭·키·휠·대상 창을 같은 시간축에 저장합니다.
- 종료 후 한 줄 목적을 입력하면 `recording.mp4`, `actions.json`, 판단용 `prompt.txt`를 하나의 ZIP으로 내보냅니다.
- 이 테스트는 노드나 JSON을 만들지 않고 GPT가 작업 흐름과 자동화 가능성을 어느 정도 이해하는지 먼저 확인합니다.
- 액션 JSON의 실제 입력 문자는 마스킹하며, 대용량 화면 캡처 데이터는 제외해 분석 시간을 줄였습니다.

## 2.43.0 · AI 전체 기능 계약 및 고속 행동 학습

- OCR·변수·조건·반복·서브매크로·테이블·Excel·비활성 클릭·모바일 알림을 포함한 전체 노드 명세와 생성 전 검증 목록을 패키지 최상단에 제공합니다.
- 직접 실행, 프로세스 시작·종료, 창 나타남, 이미지 나타남, OCR 숫자 조건, 날짜·요일 시간 등 모든 이벤트 트리거를 AI JSON으로 가져올 수 있습니다.
- 행동 학습 패키지는 모든 시연의 PNG·대상·타임라인을 고유 ID로 합쳐 반환 JSON이 실제 자산을 정확히 다시 연결합니다.

- 행동 시연은 MP4 인코딩과 중복 명세 복사를 생략하고 무손실 PNG·구조화 타임라인만 사용해 녹화 종료 후 저장 시간을 단축합니다.

## 2.42.0 · 행동별 AI 플레이 학습

- 메인 AI 진입점을 `AI 플레이 학습`으로 바꾸고, 골드 강화·퀘스트·유물 합성처럼 자동화 목적을 행동 단위로 등록할 수 있습니다.
- 각 행동에 `기본`, `변형`, `실패·복구` 시연을 2~3회 누적하고 준비 상태를 바로 확인합니다.
- 여러 시연의 무손실 PNG·영상·타임라인을 행동별로 보존한 통합 ZIP과 전용 프롬프트를 한 번에 생성합니다.
- AI가 반복 시연의 공통 규칙과 우연한 커서 이동을 구분하고, 행동 우선순위·완료 확인·재시도·복구를 포함한 하나의 MacroRelay JSON을 만들도록 요청합니다.
- 기존 단일 AI 녹화는 `AI 도구` 메뉴에 남겨 기존 작업 방식과 패키지 가져오기를 계속 사용할 수 있습니다.

- AI 녹화 중 우클릭한 위치는 실제 우클릭 대신 `화면 조건` PNG 표식으로 기록되며, 성공 동작과 다음 조건 실패 경로를 AI JSON에 구성합니다.
- Python ABI 전용 OpenCV 패키지 우선순위를 보장하고, 다른 런타임으로 실행 중인 상주 엔진을 자동 교체합니다.
- 검색 영역이 이미지보다 작아진 경우 현재 프로그램 전체 또는 가상 화면 전체로 자동 보정합니다.
- 삭제된 노드선의 예약된 경로 손잡이 갱신을 무효화해 `EdgeItem already deleted` 오류를 제거합니다.

## 2.36.0 화면 트리거·노드 이미지 바로 편집·낮은 창 높이 대응

- AI 녹화로 만든 이미지 시작 조건을 실행 단계와 분리된 `화면 트리거` 카드로 표시합니다.
- 이미지 서치 노드의 미리보기 아이콘을 클릭하면 이미지 상세 편집을 바로 열며, 멀티 서치는 썸네일로 편집 대상을 선택합니다.
- 단계 설정을 세로 스크롤 구조로 바꾸고 입력 높이를 고정해 작은 창에서도 텍스트가 잘리지 않습니다.

## 2.35.2 프롬프트 복사 후 숨은 모달 잠금 제거

- 실제 AI 녹화 → 시작 화면 지정 → 패키지 생성 → 프롬프트 복사 순서에서 메인 창이 클릭되지 않는 현상을 재현해 수정했습니다.
- 녹화 종료 후 실행 조건 창의 중첩 `exec()` 이벤트 루프를 제거하고 완전한 비모달·비동기 흐름으로 변경했습니다.
- 실행 조건 창이 닫힌 다음 새 이벤트 루프에서 패키지를 만들고 완료 알림을 표시하므로 Windows 네이티브 창의 비활성 상태가 남지 않습니다.
- 프롬프트 복사 후 이미지 편집 등 메인 메뉴를 즉시 사용할 수 있는 회귀 테스트를 추가했습니다.

## 2.35.1 AI 캡처 후 입력 잠김 수정

- 특정 화면 캡처 중 메인 창을 숨겼다가 복원하면서 Windows의 모달 입력 차단이 남는 문제를 수정했습니다.
- 메인 창은 숨기지 않고 캡처 중에만 투명하게 처리하여 창 소유 관계를 유지합니다.
- 패키지 생성 완료 알림과 프롬프트 복사는 비모달 방식으로 바꿔, 알림이 보이지 않더라도 Studio를 클릭하거나 종료할 수 있습니다.
- 실행 조건 창을 완전히 정리한 다음 별도 이벤트 루프에서 완료 알림을 표시합니다.

## 2.35 AI 녹화·가져오기 자동화

- 사용자는 별도 녹화 스위치 없이 평소처럼 작업하며, 영상은 각 클릭·입력 전후 약 2초 구간만 자동 보관합니다.
- `F8`은 선택 사항인 중요 화면 표시입니다. 지정한 원본 PNG는 시작·성공·실패 화면 판정 후보로 패키지에 포함됩니다.
- 같은 실행 파일과 창 클래스의 제목 변화는 하나의 대상 프로그램으로 자동 병합합니다.
- ChatGPT는 1회 실행, 3회 재시도, 500ms 간격, 실패 시 정지 같은 안전 기본값을 사용하고 정말 막히는 정보 하나만 질문합니다.
- 가져오기 화면은 `모두 자동 확인 → 한 번 테스트 → 사용 시작`의 세 단계로 단순화했으며 세부 표와 직접 수정 기능은 기본적으로 접혀 있습니다.
- 이미지 자산·클라이언트 좌표·클릭 오프셋·자동 비활성 클릭은 패키지 메타데이터로 준비하고, 비밀번호나 보안 값처럼 자동 결정할 수 없는 항목만 남깁니다.

## 2.34.1 AI 시작 화면 캡처 안정화

- AI 시작 화면은 드래그를 놓는 즉시 캡처를 완료해 정지 화면에 갇히는 현상을 방지합니다.
- 캡처 창이 닫히거나 오류가 나도 Studio와 실행 조건 창을 항상 복원합니다.
- 시작 화면 캡처 직후 `누끼·상세 편집`에서 자동 누끼, 투명화 붓, 색상 제거와 자르기를 사용할 수 있습니다.

## 2.34 AI 실행 조건 단순화

- AI 녹화가 끝난 뒤 `내가 직접 실행` 또는 `특정 화면이 나타나면 자동 실행`만 선택합니다.
- 시작 화면은 기존 다중 모니터 PNG 캡처와 이미지 자산 시스템으로 저장하고 대상 프로그램 클라이언트 영역에서 확인합니다.
- 자동 실행은 화면이 `없음 → 있음`으로 바뀐 뒤 500ms 동안 안정적으로 유지될 때 한 번만 실행합니다.
- 시작 화면이 계속 보이면 반복하지 않으며, 사라진 뒤 다시 나타날 때 재실행됩니다.
- 실행 조건과 기본 실패 정책은 AI 분석 패키지와 JSON 가져오기 흐름에 보존됩니다.
- 설정 화면에서는 Trigger, Polling, Edge, Cooldown 같은 내부 용어를 표시하지 않습니다.

## 2.33 AI 자동 매크로 제작

OpenAI API나 API 키를 연결하지 않고도 한 번의 일반 조작 녹화에서 ChatGPT 분석 패키지를 만들고, ChatGPT가 작성한 MacroRelay JSON을 안전한 노드 초안으로 가져올 수 있습니다.

1. 매크로 빌더에서 `AI 매크로 녹화`를 누르고 평소처럼 작업한 뒤 `F10`으로 종료합니다.
2. `exports/ai-recordings/`에 생성된 ZIP과 `ChatGPT용 프롬프트 복사`의 내용을 ChatGPT에 첨부합니다.
3. ChatGPT는 기록이 명확하면 안전 기본값으로 JSON을 바로 만들고, 반드시 필요한 정보가 빠진 경우에만 질문 하나를 합니다. 내려받은 JSON을 `AI JSON 불러오기`로 엽니다.
4. 통합 확인 화면에서 `모두 자동 확인`, `한 번 테스트`, `사용 시작` 순서로 진행합니다. 자동 결정할 수 없는 보안 값만 직접 설정합니다.

분석 ZIP에는 동작 영상, 클릭·더블클릭·드래그·휠·단축키 타임라인, 대상 프로그램/DPI/클라이언트 좌표, 클릭 전후 무손실 PNG, 작은·버튼·넓은·흑백·윤곽·배경 제거 후보, 접촉 시트와 엄격한 `macrorelay-ai-1.0` 스키마가 포함됩니다. 영상 프레임은 이미지 서치 자산으로 사용하지 않습니다.

문자 입력은 녹화 시점부터 `[REDACTED]`로 저장되고 입력 구간 영상과 PNG의 입력 컨트롤은 가려집니다. 민감 값은 `설정 > 보안 보관함`의 DPAPI 항목 이름으로만 참조합니다. AI JSON은 허용 액션만 가져오며 Python·AHK·PowerShell·셸 코드는 거부합니다. 모든 가져오기는 새 `AI 초안`으로 저장되고, 주황색 설정 필요 노드는 정식 실행·Quick Slots·원격 실행이 차단됩니다. 드라이런과 단일 단계 테스트만 허용되며 `미완성 설정 계속하기`에서 언제든 이어서 설정할 수 있습니다.

## 2.32 안정성·자동 실행 기능

- 노드별 재시도와 간격, 실패선 전환, 연속 실패 자동 정지, 체크포인트 자동 재개
- 서브플로우 입력·출력 변수와 성공 결과 변수
- 실제 클릭·입력 없이 경로와 예상 동작을 확인하는 드라이런
- 화면 캡처 재사용, 템플릿 사전 로딩, 이전 탐지 위치 우선 검색을 포함한 이미지 검색 캐시
- 프로그램 시작·종료, 창/이미지 출현, OCR 숫자 조건, 시간·요일 기반 자동 실행
- 이미지/OCR/변수 입력과 기대 경로·클릭 횟수를 저장하는 매크로 회귀 테스트
- Windows 사용자 DPAPI로 암호화되는 보안 보관함과 실행 중 변수 불러오기 노드
- 노드 평균·최대 시간, 실패율, 이미지 검색 시간, OCR 성공률, 캡처 재사용, CPU·메모리 통계

이벤트 조건과 테스트 케이스는 매크로 빌더의 `더보기` 메뉴에서 설정합니다. 보안 값은 `설정 > 보안 보관함`에 저장한 뒤 `보안 보관함 값 불러오기` 노드에서 이름만 참조합니다. 포터블 내보내기에는 참조된 값의 DPAPI 암호문만 포함되며 평문은 포함되지 않습니다. 기존 모바일 연결 키도 첫 실행 때 DPAPI 보관함으로 자동 이전되어 `remote_config.json`에서 제거됩니다.

## 구조

- `macro_tool.py` : CLI를 통해 매크로를 만들고, 단계(step)를 추가하며, `.ahk`로 내보냅니다.
- `macros/` : 각 매크로 정의(JSON 파일)가 들어 있는 폴더.
- `assets/` : 이미지 검색에 쓸 PNG/JPG 파일을 저장하고 `index.json`에서 별칭(alias)으로 관리합니다.
- `exports/` : `export` 명령으로 만들어진 `.ahk` 파일이 위치합니다. 이 경로를 울란도 스트림덱 버튼에서 호출하면 됩니다.

## 기본 사용 흐름

### Studio 실행

`run_studio.bat`을 실행합니다. Studio에서 매크로 생성, 단계 추가, 이미지 캡처·편집, Quick Slots와 기능별 단축키 설정, `.ahk` 내보내기를 진행할 수 있습니다.

새 PC에서는 [최신 릴리스](https://github.com/shinhuigwan/macrorelay-studio/releases/latest)의 `MacroRelay-Studio-v*.zip`을 내려받고 `setup_windows.bat`을 한 번 실행하세요. Python이 없으면 자동 설치하고 멀티 이미지 서치에 필요한 OpenCV·MSS·NumPy까지 구성한 뒤 Studio를 시작합니다.

### CLI

1. 매크로 만들기
```bash
python macro_tool/macro_tool.py new "인벤토리 정리" --description "인벤 정리용 클릭 순서"
```

2. 단계 추가
   - 단순 클릭:
   ```bash
   python macro_tool/macro_tool.py add-step "인벤토리 정리" \
       --action mouse_click --param x=120 --param y=340 --param button=Left --param sleep_after=300
   ```
   - 이미지 검색 + 클릭:
   ```bash
   python macro_tool/macro_tool.py add-step "인벤토리 정리" \
       --action image_search \
       --json '{"asset":"purchase-button","click":{"offset":[0,5],"button":"Left","count":1},"timeout":4000}'
   ```

3. 이미지 에셋 관리
   - 등록: `macro_tool/assets` 하위로 복사하고 alias(예: `purchase-button`)를 기록합니다.
   ```bash
   python macro_tool/macro_tool.py asset add C:/Users/shin/Downloads/buy.png --alias purchase-button
   ```
   - 목록/삭제: `asset list`, `asset remove purchase-button`

4. `.ahk`로 내보내기
```bash
python macro_tool/macro_tool.py export "인벤토리 정리"
```
`exports/인벤토리-정리.ahk` 같은 파일이 생성됩니다.

## Ulando 스트림덱에 연결하기

1. `AutoHotkey.exe`를 설치한 위치를 확인합니다. 기본적으로 `"C:\Program Files\AutoHotkey\AutoHotkey.exe"`입니다.
2. 스트림덱의 버튼 액션에 다음과 같은 명령을 넣습니다.
   ```
   "C:\Program Files\AutoHotkey\AutoHotkey.exe" "<MacroRelay 경로>\exports\인벤토리-정리.ahk"
   ```
3. 버튼이 눌리면 해당 `.ahk`에서 정의한 단계가 순차적으로 실행되고, 필요한 경우 이미지가 `assets/` 폴더에서 참조됩니다.

## 주요 명령 요약

- `macro_tool.py list` : 저장된 매크로 이름과 설명 확인
- `macro_tool.py describe <name>` : JSON 출력
- `macro_tool.py add-step` : `--action`과 `--param`/`--json`으로 순서를 정의
- `macro_tool.py export <name>` : `.ahk` 파일 생성 (`exports/`에 저장)
- `macro_tool.py asset add/remove/list` : 이미지 검색용 자산 관리

## 이미지 검색 단계 예시

JSON에서 `click` 매개변수는 `{"offset":[dx,dy],"button":"Left","count":1}` 형태로, 검색 결과 좌표를 기준으로 오프셋을 덧셈합니다. `timeout`을 주면 지정한 밀리초까지만 검색하고 없으면 종료합니다. `abort_on_fail`을 `false`로 바꾸면 실패해도 다음 단계로 이어집니다.

## 모바일 원격 제어

Studio의 `설정 > 모바일 원격`에서 원격 제어를 켜면 Studio가 실행되는 동안 저전력 PC 에이전트가 인터넷 중계 서버와 연결을 유지합니다. 매크로가 실행 중이지 않아도 다른 Wi-Fi나 모바일 데이터의 휴대폰에서 연결할 수 있으며, 6자리 코드로 연결하면 매크로 조회·실행·정지 및 완료 알림을 사용할 수 있습니다. 공유기 설정이나 포트 포워딩은 필요하지 않습니다.

Android에서는 [최신 릴리스](https://github.com/shinhuigwan/macrorelay-studio/releases/latest)의 `MacroRelay-Remote-*.apk`를 내려받아 설치할 수 있습니다. 최신 APK에는 고정 HTTPS 주소가 포함되어 있어 주소 입력 없이 바로 열립니다. APK 소스는 `android/`에 있으며, 로컬에서는 `android/gradlew.bat assembleDebug`로 다시 빌드할 수 있습니다.

인터넷 외부 접속, 권한 모델, 설치형 PWA와 서버 운영 방법은 [REMOTE.md](REMOTE.md)를 참고하세요. `remote_config.json`에는 기기 비밀 키가 있으므로 Git에 포함하지 마세요.
